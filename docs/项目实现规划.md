## 2. 代码事实与设计边界

已读取 README.md、main.py、app/models.py、app/schemas.py 和四个业务路由文件。

| 模块 | 现有能力 | 对前端的影响 |
| --- | --- | --- |
| 用户 | POST /users、POST /auth/login、GET /users/me | 用户名密码注册登录；可显示当前用户名 |
| 任务 | POST/GET /tasks，GET/PATCH/DELETE /tasks/{task_id} | 可创建、查询、修改标题和完成状态、删除；用户数据隔离 |

| 更新机制 | 普通 HTTP 请求，无推送接口 | 操作成功立即更新；回到前台刷新；定时轮询同步 |
| 前端工程 | 实施前只有被 Git 忽略的 HTML/JS 登录演示，无工程化前端 | 实施时备份旧演示并建立前端工程、路由、样式和接口封装 |
| CORS | 当前只允许 http://127.0.0.1:5173 | 开发地址与后续部署来源需匹配 |

## 4. 页面与交互设计（模型建议）

### 4.1 页面结构

- 登录页 /login：桌面左右分区，左侧简洁品牌和学习主题图形，右侧表单；手机只保留紧凑品牌和表单。支持显示密码、提交中状态和错误提示。
- 注册页 /register：与登录页统一，包含用户名、密码、确认密码；成功后返回登录并预填用户名，不保留密码。
- 我的任务 /tasks：默认主页面。桌面左侧导航，顶部标题和用户菜单，内容区按“简要统计 → 搜索筛选 → 任务列表”排列。
- 任务记录 /task-logs：按时间倒序展示时间线，按日分组；顶部任务 ID 和操作类型筛选；展开可看字段前后变化，不直接展示原始 JSON。
- 任务编辑：桌面使用右侧抽屉，手机使用全屏面板，避免编辑时失去列表上下文。显示标题、完成状态及该任务记录入口。

导航仅保留“我的任务”“任务记录”，底部用户菜单提供退出。手机采用顶部品牌与底部两项导航。退出、注册和登录均有清晰返回路径。

### 4.2 任务页信息层级

1. 标题“我的任务”，右侧主按钮“新建任务”。
2. 全部、未完成、已完成三个简洁数量摘要；仅在能准确取得全量统计时显示，不能用当前页数量冒充全量。
3. 标题搜索框，状态标签“全部 / 未完成 / 已完成”，无学科或自定义类别。
4. 任务列表以标题为核心，左侧完成勾选，右侧状态与编辑/更多菜单；已完成用文字状态和适度弱化表达，长标题换行。
5. 底部分页或加载更多，具体依据接口返回信息确定；不伪造总页数。

新建与编辑共用表单。标题去首尾空白后 1～200 字；提交期间防重复点击。关闭未保存的编辑时提示是否放弃。

完成/恢复操作成功后刷新受影响的列表、统计和历史；若任务因当前筛选条件消失，给出清晰提示。删除前确认并显示任务标题，说明历史仍保留；不提供当前后端无法兑现的删除撤销。

### 4.3 视觉方案

- 整体：安静、清爽的浅色学习工作台，以留白和对齐建立层级。
- 页面背景：浅灰蓝 #F6F8FC；卡片和侧栏：白色 #FFFFFF。
- 主色：蓝色 #2563EB；主文字：深灰蓝 #172033；次文字：#5B677A；边框：#E2E8F0。
- 成功状态：绿色配文字和图标；危险操作：红色，仅用于必要的删除及错误提示。
- 标题约 24～28px，正文 14～16px，行高约 1.5；优先系统中文字体。
- 统一间距采用 8px 节奏，面板圆角约 12px，阴影克制。图标统一线性风格，主要入口保留文字。
- 动效约 150～200ms；尊重减少动画偏好。实施时核查文本、边框、焦点及各状态的可辨识性。

### 4.4 响应式与状态反馈

- 桌面约 1024px 起：固定侧栏，宽内容列表；大屏限制内容最大宽度。
- 平板：紧凑导航，搜索和筛选允许换行。
- 手机约 640px 以下：单列任务卡片，底部导航，触控目标约 44px，表单全宽。
- 首次加载用骨架；后台同步保留旧数据并标注同步状态；首次无任务显示新建入口；无搜索结果提供清空筛选；请求失败提供重试。
- 表单错误就近显示，操作结果用简短提示。对话框管理焦点，支持键盘关闭及返回原入口。

## 5. 搜索与更新方案（根据用户约束修订）

后端、数据库、接口、CORS 均不修改。不增加搜索接口、统计接口、分类字段或推送通道。前端开发固定使用现有允许的 http://127.0.0.1:5173；生产环境通过同源反向代理对接接口。

前端搜索与状态筛选建议：使用 GET /tasks?offset=0&limit=100 开始顺序分批读取，最后一批不足 100 条时结束（正好整百时需要额外空页确认）；在内存中按 ID 去重，完整成功后统一替换当前任务集合，再按关键词和 completed 过滤，最后执行前端分页。关键词约 300ms 防抖，切换条件回到第一页。数量摘要仅在完整加载成功后展示。

首次完整读取期间显示加载进度，不显示误导性的全量数量或“无搜索结果”。任意一批失败视为同步未完成，允许重试；后台刷新失败保留上一轮完整数据并标示同步失败。切换账号、退出和会话过期时取消旧请求并清理缓存。

此方法不改后端，适合个人任务规模。首次加载请求数随任务数量增加；现有 offset 分页不保证并发修改时的快照一致性，刷新和下一次同步负责收敛。若实际数据量导致不可接受的加载耗时，按用户许可移除标题搜索和全量数量摘要，并重新对齐状态筛选的展示范围，不擅自修改后端。第一版无截止日期、优先级或日历。

同步方案已确认，具体间隔建议为 30 秒：变更成功立即按服务端结果更新本地任务集合，记录缓存失效；窗口回到前台重新获取数据；可见且已登录页面定时轮询，页面隐藏时暂停，失败退避并可手动重试。刷新任务时重新完整读取，串行执行同步，避免轮询重叠；编辑草稿不会被后台数据覆盖。操作请求前已发出的旧查询取消或丢弃，避免旧结果覆盖最新操作。此方案存在秒级延迟。

任务记录继续使用现有服务端 task_id/action 筛选及分页；不提供现有接口无法直接支持的全历史关键词搜索。记录页约每 30 秒刷新已查看部分，采用“加载更多”，不伪造总记录数。
