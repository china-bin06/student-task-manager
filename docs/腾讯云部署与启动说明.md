# 腾讯云部署与启动说明

适用项目：学生任务管理系统（React + FastAPI + PostgreSQL）。

用途：在腾讯云轻量应用服务器上练习部署、展示作品。参考环境为 Ubuntu 24.04 LTS、2 核 2GB、Docker Engine、Compose 插件和 Nginx。

本文根据项目配置及本次部署排错整理；服务器最终运行结果需按第 7 节验证。文档不包含真实密码和密钥。

## 1. 部署结构与命令位置

```text
浏览器 → 公网 IP:80 → Nginx
                       ├── /          → 前端静态文件
                       └── /api/      → 127.0.0.1:8000 → FastAPI
                                                          ↓
                                                    PostgreSQL
```

| 环境 | 用途 | 目录 |
| --- | --- | --- |
| 本地 Windows PowerShell | 构建前端、上传文件 | D:\agent项目\学生任务管理系统 |
| Ubuntu 服务器终端 | 配置、运行、排错 | /home/ubuntu/student-task-manager |
| 服务器静态站点目录 | Nginx 读取前端文件 | /var/www/student-task-manager/dist |

`/` 开头的路径是绝对路径。例如 `sudo mkdir -p /var/www/student-task-manager/dist` 在任何工作目录执行，创建的位置都相同。

首次部署使用新的线上数据库，本地 SQLite 或 PostgreSQL 中的账号、任务不会自动迁移。

## 2. 腾讯云控制台配置与登录

1. 确认服务器运行中，记录公网 IP。
2. 重置实例的 `ubuntu` 用户密码。控制台免密登录成功，不代表本地 SSH 密码已配置好。优先选择在线重置；离线重置会中断服务器运行。
3. 配置实例防火墙：TCP 80 用于 HTTP、TCP 443 用于后续 HTTPS，来源可设置为 `0.0.0.0/0`；TCP 22 用于 SSH，优先仅允许本机公网 IP。
4. 不向公网开放 8000、5432、5433、5173。现有 Compose 将后端和数据库端口绑定到服务器回环地址。

**本地 PowerShell：**

```powershell
$serverIp = "替换为服务器公网IP"
ssh "ubuntu@${serverIp}"
```

首次连接时确认主机身份后接受指纹；输入密码时不显示字符或星号。提示符变成 `ubuntu@...:~$` 即已进入服务器。输入 `exit` 返回本地 PowerShell。

## 3. 安装运行环境

### 3.1 Nginx 与基础工具

**服务器终端：**

```bash
sudo apt update
sudo apt install -y nginx curl ca-certificates nano openssl
sudo systemctl enable --now nginx
mkdir -p /home/ubuntu/student-task-manager
```

本地浏览器访问 `http://服务器公网IP`，预期显示 Nginx 欢迎页。

### 3.2 Docker 与 Compose

如果已安装并通过下面检查，跳过安装：

```bash
sudo docker version
sudo docker compose version
```

安装参考 [Docker Ubuntu 官方文档](https://docs.docker.com/engine/install/ubuntu/)和[腾讯云 Docker 安装说明](https://cloud.tencent.com/document/practice/213/46000)。以下供首次安装使用：

```bash
sudo mkdir -p /etc/apt/keyrings
sudo curl -fsSL --connect-timeout 15 https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
```

下载成功后添加软件源，最后一行 `EOF` 也要复制：

```bash
sudo tee /etc/apt/sources.list.d/docker.sources > /dev/null <<EOF
Types: deb
URIs: https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu
Suites: noble
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

`noble` 对应 Ubuntu 24.04。若此前已经创建其他 Docker 软件源文件，应先检查并合并，避免重复配置同一仓库或冲突的签名密钥。

```bash
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker version
sudo docker compose version
```

### 3.3 配置 Docker 镜像加速

安装 Docker 的 APT 软件源和下载容器镜像的加速源是两套配置。遇到 `registry-1.docker.io` 连接超时时，配置下面的镜像加速。

```bash
sudo nano /etc/docker/daemon.json
```

空文件填入以下内容；已有其他字段时保留并合并，不要追加第二个 JSON 对象：

```json
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com"
  ]
}
```

Nano 保存方式：`Ctrl+O` → 回车 → `Ctrl+X`。

```bash
sudo dockerd --validate --config-file=/etc/docker/daemon.json
```

验证成功再重启。重启 Docker 可能中断正在运行的容器：

```bash
sudo systemctl restart docker
sudo docker info --format '{{json .RegistryConfig.Mirrors}}'
sudo docker pull python:3.12-slim
sudo docker pull postgres:18
```

该镜像地址仅支持腾讯云内网，具体版本能否拉取以实际结果为准。参考[腾讯云轻量服务器镜像加速说明](https://cloud.tencent.cn/document/product/1207/45596)。

## 4. 本地构建与上传

### 4.1 构建前端

**本地 PowerShell：**

```powershell
cd 'D:\agent项目\学生任务管理系统'
npm --prefix frontend ci
$env:VITE_API_BASE_URL = "/api"
npm --prefix frontend run build
Remove-Item Env:VITE_API_BASE_URL
```

构建成功后会生成 `frontend/dist`。构建失败时先修复错误，不上传旧产物。服务器无需安装 Node.js。

`VITE_API_BASE_URL` 是构建时配置；修改后需重新构建。不能使用 `http://127.0.0.1:8000` 作为线上前端地址，它会指向访问者自己的电脑。

### 4.2 处理 pip 下载超时

v3 Dockerfile 已支持 `PIP_INDEX_URL` 构建参数，默认使用官方 PyPI，并设置超时和重试。国内服务器下载依赖超时时，可在服务器项目目录执行：

```bash
sudo docker compose --progress plain build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple api
```

不需要修改 Dockerfile，也不需要升级 pip 或清空缓存。每次重新构建时按需带上此参数，已经运行的容器不依赖该参数。仅传公开、不含凭证的镜像 URL，因为构建参数不适合保存秘密。保留依赖版本约束；如果镜像缺少某个版本，先检查镜像同步或版本可用性。

参考[清华 PyPI 镜像说明](https://mirror.tuna.tsinghua.edu.cn/help/pypi/)。只改服务器系统的 pip 配置，不会自动影响 Docker 构建中的 pip。

### 4.3 上传文件

先确认服务器已创建 `/home/ubuntu/student-task-manager`。在本地项目根目录执行：

```powershell
$serverIp = "替换为服务器公网IP"
scp -r app migrations deploy frontend/dist main.py alembic.ini requirements.txt Dockerfile compose.yaml .dockerignore .env.api.example .env.postgres.example "ubuntu@${serverIp}:/home/ubuntu/student-task-manager/"
```

只上传模板，线上密码单独配置。不上传本地 `.env`、`.env.api`、`.env.postgres`、数据库文件、`.venv` 或 `node_modules`。

**服务器终端：**

```bash
cd /home/ubuntu/student-task-manager
ls -la
```

确认存在 `app`、`migrations`、`deploy`、`dist`、`main.py`、`alembic.ini`、`requirements.txt`、`Dockerfile`、`compose.yaml`、`.dockerignore` 和两份配置模板。

## 5. 首次配置和启动后端

以下命令均在服务器项目目录执行：

```bash
cd /home/ubuntu/student-task-manager
cp -n .env.api.example .env.api
cp -n .env.postgres.example .env.postgres
```

`-n` 避免覆盖已有配置。已有线上数据库时沿用现有凭证，不要重新生成密码。

### 5.1 首次设置密钥

分别生成数据库密码和 JWT 密钥，妥善保存，不发到聊天中：

```bash
openssl rand -hex 24
openssl rand -hex 32
```

编辑数据库配置：

```bash
nano .env.postgres
```

替换占位符，内容为：

```dotenv
POSTGRES_USER=student_app
POSTGRES_PASSWORD=替换为第一次生成的数据库密码
POSTGRES_DB=student_tasks
```

编辑后端配置：

```bash
nano .env.api
```

```dotenv
APP_NAME="学生任务管理系统"
DATABASE_URL=postgresql+psycopg://student_app:替换为同一个数据库密码@postgres:5432/student_tasks
JWT_SECRET_KEY=替换为第二次生成的64字符JWT密钥
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

使用生成的十六进制值替换占位符，不添加空格。`postgres:5432` 保持不变，它是 Compose 内部地址。JWT 密钥至少 64 个字符。

数据库初始化后，单独修改配置文件不会更改库内用户密码；修改 JWT 密钥会使原有令牌失效。

### 5.2 配置自动恢复

v3 的 `compose.yaml` 已为 `api` 和 `postgres` 配置 `restart: unless-stopped`，不需要另建覆盖文件。此前按旧教程创建的同内容 `compose.override.yaml` 可继续保留，Compose 会自动合并。

Docker 服务随开机启动，运行中的容器可在异常退出或服务器重启后恢复；主动 `stop` 的容器需要手动启动。

### 5.3 构建并迁移

逐条执行，出现错误先停止后续操作：

```bash
sudo docker compose config --quiet
sudo docker compose --progress plain build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple api
sudo docker compose up -d postgres
sudo docker compose ps
```

等待 PostgreSQL 显示 `healthy` 再执行：

```bash
sudo docker compose run --rm api python -m alembic upgrade head
sudo docker compose up -d api
curl -f http://127.0.0.1:8000/health
```

预期返回 `{"status":"ok"}`。此接口只证明应用响应，数据库还需通过注册和任务操作验证。

## 6. 发布前端与配置 Nginx

### 6.1 放置静态文件

**服务器终端：**

```bash
sudo mkdir -p /var/www/student-task-manager/dist
sudo cp -r /home/ubuntu/student-task-manager/dist/. /var/www/student-task-manager/dist/
```

不需要递归放宽项目或系统目录权限；本流程不要求 `chmod 777`。如果排错时临时修改了已有文件或目录的权限，处理完成后恢复原权限。

### 6.2 创建站点

项目已提供相同内容的模板，新部署可以直接复制，再按需编辑：

```bash
sudo cp /home/ubuntu/student-task-manager/deploy/nginx.conf /etc/nginx/sites-available/student-task-manager
```

如果该站点已有域名或 HTTPS 等自定义配置，先备份并合并，不要覆盖。查看或编辑使用：

```bash
sudo nano /etc/nginx/sites-available/student-task-manager
```

填入：

```nginx
server {
    listen 80;
    server_name _;

    root /var/www/student-task-manager/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`proxy_pass` 最后的 `/` 必须保留，用于将 `/api/users` 转发为后端的 `/users`。前端与接口同源，不需要为此放宽后端 CORS。

`try_files` 用于支持刷新 `/tasks` 等前端路由。

### 6.3 启用并验证

```bash
sudo ln -sfn /etc/nginx/sites-available/student-task-manager /etc/nginx/sites-enabled/student-task-manager
```

对于这台新建、只部署一个项目的服务器，停用默认欢迎页链接；保留原配置文件：

```bash
if [ -L /etc/nginx/sites-enabled/default ]; then
    sudo unlink /etc/nginx/sites-enabled/default
fi
```

```bash
sudo nginx -t
```

检查成功后：

```bash
sudo systemctl reload nginx
curl -f http://127.0.0.1/api/health
```

预期返回 `{"status":"ok"}`。

## 7. 浏览器验证

在本地浏览器地址栏输入 `http://服务器公网IP`，不是在终端执行。

1. 确认显示项目登录页。
2. 注册专用演示账号并登录。
3. 创建、修改、完成和删除任务，查看操作历史。
4. 刷新 `/tasks`、`/task-logs`，确认不会出现 Nginx 404。
5. 退出并重新登录，确认数据仍在。

HTTP 阶段用于部署验证。正式展示登录功能前配置 HTTPS；使用大陆服务器通过域名公开提供网站服务，应完成所需备案。域名解析到公网 IP 后，更新 Nginx 的 `server_name`，安装证书，再验证 HTTPS 页面和 `/api/health`。

## 8. 日常启动、停止与日志

### 8.1 启动项目

先登录服务器：

```powershell
ssh ubuntu@替换为服务器公网IP
```

服务器中执行：

```bash
cd /home/ubuntu/student-task-manager
sudo systemctl start docker
sudo systemctl start nginx
sudo docker compose up -d
sudo docker compose ps
curl -f http://127.0.0.1/api/health
```

`-d` 表示后台运行。之后关闭 SSH 终端，服务仍继续运行。日常启动不用重新构建，也不用重新生成密钥。

### 8.2 停止与恢复

```bash
cd /home/ubuntu/student-task-manager
sudo docker compose stop
```

此操作停止后端和数据库，保留数据；Nginx 静态页面仍可访问，接口会暂时不可用。需要同时关闭网页服务时执行 `sudo systemctl stop nginx`。

恢复使用第 8.1 节命令。

**不要使用 `sudo docker compose down -v` 作为停止命令，`-v` 会删除数据库卷。**

### 8.3 重启与查看日志

只重启现有后端容器：

```bash
sudo docker compose restart api
```

修改源码或 `.env.api` 后，单纯 `restart` 不会应用全部变更，按第 9 节重新构建或创建容器。

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 api
sudo docker compose logs --tail=100 postgres
sudo docker compose logs -f api
```

跟随日志时按 `Ctrl+C` 只停止日志查看，不会停止服务。

Nginx 排错：

```bash
sudo nginx -t
sudo systemctl status nginx --no-pager
sudo tail -n 80 /var/log/nginx/error.log
```

## 9. 更新项目与备份

### 9.1 更新前备份数据库

**服务器终端，数据库运行且健康时：**

```bash
cd /home/ubuntu/student-task-manager
mkdir -p backups
sudo docker compose exec -T postgres pg_dump -U student_app -d student_tasks -Fc > "backups/student_tasks-$(date +%Y%m%d-%H%M%S).dump"
```

确认命令成功、备份文件非空，并定期下载到本地保存。备份包含业务数据，勿放到 `/var/www`。数据库使用命名卷 `postgres_data` 持久化，具体卷名可用 `sudo docker volume ls` 查看；不要删除它来处理启动故障。

### 9.2 更新后端

重新上传变化的源码、依赖文件和迁移文件，保留服务器 `.env.api`、`.env.postgres`，以及存在的自定义覆盖配置。v3 上传 Dockerfile 后无需再手工修改镜像源，构建时使用参数选择。

对于该演示项目，可安排短暂维护：先备份，再构建，构建成功后暂停后端、执行迁移并恢复服务：

```bash
cd /home/ubuntu/student-task-manager
sudo docker compose build --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple api
```

构建成功后继续：

```bash
sudo docker compose stop api
sudo docker compose run --rm api python -m alembic upgrade head
```

迁移成功后：

```bash
sudo docker compose up -d api
curl -f http://127.0.0.1/api/health
```

迁移失败时不要继续发布或删除数据，先查看报错。更新 `.env.api` 后可执行 `sudo docker compose up -d --force-recreate api` 使配置生效。数据库凭证变更还必须与数据库内实际凭证保持一致。

### 9.3 更新前端

在本地按第 4.1 节重新构建，然后上传：

```powershell
scp -r frontend/dist "ubuntu@${serverIp}:/home/ubuntu/student-task-manager/"
```

服务器执行：

```bash
sudo cp -r /home/ubuntu/student-task-manager/dist/. /var/www/student-task-manager/dist/
```

刷新浏览器验证。只替换静态文件不需要重启 Nginx；修改 Nginx 配置才需要先 `sudo nginx -t` 再 `sudo systemctl reload nginx`。

这种覆盖方式可能保留旧的带哈希资源，适合当前演示用途，后续可增加版本目录和发布切换。

## 10. 本次常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 下载 Docker GPG 密钥时 `Connection reset by peer` | 官方下载站连接被重置，使用第 3.2 节腾讯云 APT 源 |
| SCP 提示 `Permission denied, please try again` | 登录认证未通过，重置 `ubuntu` 密码，先用 SSH 测试；不通过放宽目录权限解决 |
| 构建访问 `registry-1.docker.io` 超时 | 基础镜像拉取失败，按第 3.3 节配置加速并单独测试 `docker pull` |
| pip 报 `files.pythonhosted.org ... Read timed out` | Python 依赖下载超时，按第 4.2 节传入镜像源构建参数，重新构建 |
| 构建被 `Ctrl+C` 中断 | 可以直接重跑构建，已完成层通常可复用；失败或中断的步骤重新执行 |
| SSH 断开，不确定构建是否仍在运行 | 先用 `ps -ef \| grep '[d]ocker compose'` 查看，再决定是否重跑 |
| 网页仍是 Nginx 欢迎页 | 检查自定义站点链接、默认站点是否停用，检查配置并重载 |
| 页面显示但接口 502 | 检查 `api` 容器、后端日志及 `curl http://127.0.0.1:8000/health` |
| 页面请求自己电脑的 127.0.0.1 | 前端构建配置错误，使用 `/api` 重新构建上传 |
| 刷新 `/tasks` 返回 404 | 检查 Nginx 的 SPA 回退 `try_files` 是否生效 |
| 重启后服务未恢复 | 检查 Docker、Nginx 开机启动及 Compose 的重启策略；主动停止过的容器手动 `up -d` |

构建诊断使用：

```bash
sudo docker compose --progress plain build api
```

保留最后的错误信息定位问题。构建失败通常无需清空镜像、构建缓存或数据库卷。
