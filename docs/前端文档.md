## 2. 本地启动

验证环境：Windows PowerShell、Node.js 24.22.0、npm 11.19.1。建议使用 Node.js 24；版本固定信息见 package-lock.json。

先按照根 README 的现有步骤准备后端配置和数据库迁移，再启动后端，例如在项目根目录：

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

另开一个终端，在项目根目录执行：

```powershell
cd frontend
npm ci
npm run dev
```

浏览器打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。请使用 `127.0.0.1`：现有后端只允许这个主机在 5173 端口发起跨域请求，`localhost:5173` 是不同来源。端口已被占用时 dev 会报错，不会悄悄换端口。

默认 API 基址为 `http://127.0.0.1:8000`。需要更换时复制 frontend/.env.example 为 frontend/.env.local，调整 VITE_API_BASE_URL，然后重启开发服务；生产构建需重新构建才会生效。此变量是公开前端配置，不放 JWT 密钥或数据库密码。

## 3. 页面与使用流程

| 地址 | 页面 | 操作 |
| --- | --- | --- |
| /login | 登录 | 用户名密码登录、显示/隐藏密码、进入注册 |
| /register | 注册 | 用户名、密码、确认密码；成功后返回登录并预填用户名 |
| /tasks | 我的任务 | 概览、搜索筛选、分页、新建、编辑、完成/恢复、删除、查看记录 |
| /task-logs | 任务记录 | 按日分组的历史、任务 ID/操作类型筛选、快照差异、加载更多 |
| /task-logs?task_id=数字 | 单任务历史 | 从任务行或编辑面板进入，自动带入任务编号 |

未登录访问任务页会返回登录页。未知页面跳转到任务入口，再按当前会话决定去向。

新建任务只需要标题。编辑时可同时修改标题和状态。标题去首尾空白后不能为空，最多 200 个字符；用户名清理首尾空白，密码原样提交。关闭有改动的表单会要求选择继续编辑或放弃；普通后台同步不会覆盖已打开的编辑草稿。

删除前展示任务标题并确认，成功后任务移除，历史仍保留。前端不提供当前后端不支持的删除撤销。

## 5. 接口约定与数据流

| 接口 | 前端用途 |
| --- | --- |
| POST /users | 注册，成功后不自动保存密码或登录 |
| POST /auth/login | 发送 JSON 用户名密码，获取 Bearer token |
| GET /users/me | 确认登录用户、恢复当前会话 |
| GET /tasks?offset=&limit=100 | 完整读取个人任务 |
| POST /tasks | 新建标题任务 |
| PATCH /tasks/{id} | 更新 title 和/或 completed |
| DELETE /tasks/{id} | 删除任务，204 作为成功且不解析响应 JSON |
| GET /task-logs | 使用 task_id/action/offset/limit 筛选和分页 |

请求统一超时为 15 秒，组件查询的 AbortSignal 与超时信号组合。受保护请求附带 Authorization: Bearer，不使用 Cookie 登录。

任务与记录缓存按当前用户 ID 区分；记录缓存还区分筛选条件。退出取消所有查询、清空缓存及 sessionStorage 中的令牌。每次登录/退出递增会话代次，避免旧写请求的迟到响应或 401 影响新会话。

令牌仅保存于当前标签页的 sessionStorage；页面刷新可以恢复，浏览器禁止会话存储时回退内存。后端无刷新令牌及服务端令牌撤销，过期需要重新登录，退出为清除本地会话。

## 6. 搜索、分页和同步

现有后端没有标题搜索、状态筛选或统计接口。前端按 offset=0、100、200…顺序读取，每批最多 100 项，最后一批不足 100 项时结束；整百条数据会多请求一次空页。按任务 ID 去重，全部成功后一次替换缓存。

完整集合加载成功后，执行不区分英文大小写的标题匹配及 completed 状态过滤，再对结果分页。搜索约 300ms 防抖，改变条件回到第一页。初始完整加载之前禁用搜索/筛选，数量显示“—”；任一批失败不会把局部数据当作完整结果。后台同步失败保留上一轮完整集合并明确提示。

任务创建/修改/删除前取消旧列表查询；收到服务端成功结果后更新本地集合，并让任务和历史查询失效。不会先显示保存成功再向服务器请求。写操作期间暂停任务/历史自动查询，结束后重新同步。

页面处于前台时约每 30 秒同步；隐藏或失焦时暂停周期请求；返回前台触发刷新。失败后周期延长到约 60 秒，可手动重试。Query Observer 管理单个查询的并发，避免同一轮询重叠。历史每批 20 条，刷新已加载的各页；没有总数时采用加载更多。

限制：完整读取的请求量和耗时随任务数增加；现有 offset 分页没有并发快照保证，其他窗口在分页过程中删除任务可能造成短暂遗漏，后续完整刷新收敛。未做大规模数据压测，不宣称适合海量任务；不修改后端来消除这些限制。

## 7. 视觉、响应式及异常状态

背景浅灰蓝 #F6F8FC，主要面板白色，操作主色 #2563EB。桌面固定侧栏，平板收紧导航和内容间距，手机单列任务与底部导航。编辑面板在桌面为右侧抽屉，在手机为全屏。

首次加载有骨架；零任务与无搜索结果分别提示；接口失败有重试；后台失败显示旧数据来源；提交期间禁用重复操作；成功通过状态提示反馈。操作历史不展示原始 JSON，直接对照标题和完成状态。时间按当前设备时区显示。

按钮有语义标签与焦点样式；图标操作提供可访问名称；状态同时用文字和图形；原生 dialog 管理模态焦点、Escape 关闭和焦点返回，打开任务面板直接聚焦标题。脏表单离开有提醒，支持系统减少动画偏好。

## 9. 生产部署

执行 npm run build，将 frontend/dist 作为静态站点。服务器需对 /login、/register、/tasks、/task-logs 配置 SPA 回退，避免刷新子路由时 404。

为保持后端不变，推荐同源代理：构建前设置 VITE_API_BASE_URL=/api，站点将 /api/ 转发到 FastAPI，移除 /api 前缀。Nginx 示例（静态目录按实际部署修改）：

```nginx
server {
    listen 80;
    server_name your-domain.example;
    root /srv/student-tasks/dist;

    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

示例只提供路由关系，域名、HTTPS 和进程运维按实际环境配置；本轮未部署。不能直接将构建时的 127.0.0.1:8000 配置用于远程用户，因为它指向访问者自己的设备。
